# 구글 시트로 재실 기록 받기 (Apps Script)

서버 없이, 구글 시트 하나로 인원들의 하루 재실 요약을 모읍니다. 앱이 **매일 00:15 전후**에 어제 기록을 보내고,
같은 (날짜, 참여자 ID) 를 다시 받으면 그 기록을 덮어씁니다. 기존 `시트1` 같은 다른 탭은 건드리지 않습니다.

## 설치 (한 번만, 약 5분)
1. 구글 시트를 새로 만든다 (연구실 공용 드라이브에 만들면 편함).
2. 메뉴 **확장 프로그램 → Apps Script** 를 연다.
3. 기본으로 있는 코드를 지우고 이 폴더의 `Code.gs` 내용을 붙여 넣는다.
4. 맨 위 `TOKEN` 값을 **본인만 아는 긴 임의 문자열**로 바꾼다 (예: 영문+숫자 24자 이상). 기본값 그대로면 서버가 모든 요청을 거부한다.
5. 오른쪽 위 **배포 → 새 배포 → 유형: 웹 앱**
   - 다음 사용자로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - 처음 한 번 권한 승인 창이 뜨면 본인 계정으로 승인 (고급 → 이동 → 허용)
6. 배포가 끝나면 **웹 앱 URL** (`https://script.google.com/macros/s/.../exec`) 을 복사한다.
7. 브라우저에서 그 주소를 열어 `{"ok":true,...}` 가 보이면 정상.

## 자동 전송과 수동 전송
| | 언제 | 보내는 범위 | 시트 |
|---|---|---|---|
| 자동 | 매일 00:15 전후 | 어제까지 (확정) | 일별/세션 탭 |
| 수동 | 앱의 **서버로 지금 전송 (최근 7일)** 버튼 | 오늘 포함 최근 7일 (오늘은 진행 중인 값) | **같은 탭, 같은 형식** |

수동으로 보낸 오늘 줄은 `상태`가 **중간**으로 표시되고, 다음날 00:15 자동 전송이 같은 줄을 **확정** 값으로 덮어씁니다.
같은 날짜를 몇 번 보내도 줄이 늘어나지 않습니다.

## 기기 보관 기간
앱은 폰 안에 **최근 7일** 기록만 보관하고 그보다 오래된 것은 자동으로 지웁니다. 따라서 시트가 사실상 장기 보관본입니다.
폰이 7일 넘게 꺼져 있었거나 서버에 계속 못 보낸 날짜는 복구할 수 없습니다.

## 앱에 서버 주소 넣기 (빌드할 때 한 번)
서버 주소는 **앱 화면에서 입력하지 않고 앱에 고정으로 내장**합니다. 인원들은 주소나 토큰을 만질 일이 없습니다.

1. 웹 앱 URL 뒤에 토큰을 붙여 최종 주소를 만든다: `https://script.google.com/macros/s/AKfy.../exec?token=내TOKEN`
2. 이 주소를 앱을 빌드하는 쪽에 알려준다.
   - 로컬 빌드: `android/server.properties` 파일에 `SERVER_URL=최종주소` 한 줄 (이 파일은 git 에 올라가지 않음)
   - GitHub Actions 빌드: 저장소 Settings → Secrets → Actions 에 `SERVER_URL` 로 등록
3. 그렇게 빌드한 APK 를 인원들에게 배포한다. 앱에서는 **참여자 ID 만** 입력하면 된다 (`lab-01` 처럼 영문/숫자/-/_ 64자 이내).

주소가 앱 안에 들어 있으므로 **APK 를 받은 사람은 주소(토큰 포함)를 추출할 수 있다.** 연구실 내부 배포용으로만 쓰고,
주소/토큰이 유출되면 `TOKEN` 을 바꿔 재배포한 뒤 앱을 새 주소로 다시 빌드해 배포한다. `https://` 가 아닌 주소는 빌드가 거부된다.

수동 확인: 앱에서 참여자 ID 저장 후 **서버로 지금 전송 (최근 7일)** 을 누르면 오늘 값까지 바로 시트에 들어가므로 연결을 바로 확인할 수 있다.

## 앱에서 `Cannot read properties of null (reading 'getSheetByName')` 가 나올 때
스크립트가 시트와 연결되지 않은 **독립 프로젝트**(script.google.com 에서 새로 만든 것)라는 뜻이다. 둘 중 하나로 해결한다.
- **(권장) 코드에 시트 ID 지정**: 시트를 편집 화면으로 열었을 때 주소 `https://docs.google.com/spreadsheets/d/`**`여기`**`/edit` 의 값을
  `Code.gs` 맨 위 `SPREADSHEET_ID = ''` 의 따옴표 안에 넣는다. (웹 게시 주소의 `2PACX-…` 값이 아님) 그 뒤
  편집기에서 함수를 `setup` 으로 선택해 **실행**(시트 접근 권한 승인) → **배포 관리 → 연필 → 새 버전 → 배포**.
  **배포 주소가 그대로**라 앱을 다시 만들 필요가 없다.
- 시트의 *확장 프로그램 → Apps Script* 로 새로 열어 코드를 붙여 넣고 다시 배포한다. 이 경우 주소가 바뀌므로 앱을 다시 빌드해야 한다.

## 시트 구성
| 탭 | 내용 |
|---|---|
| **일별** | 하루(날짜×참여자)당 한 줄: `날짜, 요일, 참여자, 재실(분), 재실(시:분), 첫귀가, 마지막외출, 세션수, 앱버전, 수신시각, 상태` (`상태`: 확정/중간) |
| **세션** | 집에 머문 구간 하나당 한 줄: `날짜, 참여자, 시작, 종료, 길이(분)` (자정을 넘기면 종료가 `24:00`) |
| **요약** | 날짜×참여자 재실 분 합계표 (`setup` 실행 시 생성, 자동 계산) |
| **설명** | 열 설명 (`setup` 실행 시 생성) |

`일별`, `세션` 탭은 첫 전송 때 자동으로 만들어집니다. `요약`/`설명` 탭까지 미리 만들려면
Apps Script 편집기에서 함수 선택란을 `setup` 으로 바꾸고 **실행**을 한 번 누르세요 (권한 승인 필요).
`요약` 탭의 표는 구글 시트 수식(QUERY)이라, 이상하게 보이면 `일별` 탭 데이터가 쌓인 뒤 다시 확인하세요.

## 주의
- **"웹에 게시"는 꺼 두세요.** 시트가 *파일 → 공유 → 웹에 게시* 로 게시돼 있으면 링크를 아는 누구나 내용을 볼 수 있습니다. 실제 데이터를 받기 전에 **게시 중지**하고, 시트 공유는 연구 담당자로 제한하세요.
  (앱이 데이터를 보내는 것은 게시와 무관하며 Apps Script 웹 앱 주소로 이뤄집니다.)
- 전송 시각은 폰의 절전 상태에 따라 00:15 에서 몇 분 늦을 수 있습니다. 폰이 꺼져 있었으면 다음에 켜졌을 때 최대 14일치를 채워 보냅니다.
- **코드를 수정하면 반드시 "배포 관리 → 새 버전"으로 다시 배포**해야 반영된다 (주소는 그대로 유지됨).
- 액세스를 "모든 사용자"로 해야 앱이 접근할 수 있다. 그래서 `TOKEN` 이 유일한 보호 장치다. 유출되면 `TOKEN` 을 바꾸고 재배포한 뒤 앱 주소도 다시 입력한다.
- 주소(토큰 포함)는 인원들에게만 공유하고 공개 저장소·게시판에 올리지 말 것.
- 이 시트에는 개인의 생활 패턴이 들어간다. 시트 공유 범위를 연구 담당자로 제한하고, 참여자 동의/IRB 절차를 확인할 것.
- 구글 Apps Script 는 하루 호출량 제한이 있다(일반 계정 기준 넉넉한 수준이라 인원 수십 명 × 하루 1건은 문제없음).
- 동작 로직은 `node server/apps-script/test.mjs` 로 가짜 구글 서비스를 써서 시험할 수 있다 (실제 구글 환경에서의 배포는 직접 확인 필요).
